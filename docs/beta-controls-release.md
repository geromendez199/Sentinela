# Beta controls — 2026-10-06

This release completes the user controls around the existing backend: sign out,
password recovery, organization membership, account disconnection, synchronization
status, data filters/pagination, alert acknowledgement and navigation search.
It does not certify production readiness of the data-processing workers.

## Observed production state

A read-only inspection on October 6 found one connected account in `backfilling`.
Six historical jobs (items, orders, claims, messages, questions, shipments) were
queued without progress. All synchronization schedules were inactive; only
`sentinela-create-partitions` was active. Accordingly the UI now distinguishes
waiting work from active processing and stale processing from healthy progress.

The production member-management RPCs reject nonmembers and protect the last
owner. These existing RPCs power the new member controls; no schema migration is
needed for this release.

## Remaining operational activation

Before enabling the read/synchronization schedules, verify the deployed worker
versions, required Vault references, application secrets and the retry/refresh
migrations against the repository. Test processing with a nonproduction seller
and database before enabling the production queue consumers. Keep external write,
AI and outbound email workers disabled until their own integrations are verified.
A connected seller and a successful website build are not evidence of completed
historical synchronization.

For password recovery, the Supabase Auth redirect allowlist must include the
application callback and reset-password flow, and email delivery must be working.
The application uses `resetPasswordForEmail`, PKCE code exchange and `updateUser`;
recovery links are generated by Supabase, never by the browser UI.

## Validation

- 112 unit tests, including session boundaries, bounded list input and sync state.
- 15 existing PostgreSQL membership tests on the local validation database,
  rolled back after execution. No production membership mutation was performed.
- Lint, TypeScript and production build with local-only public configuration.
- Browser checks use temporary local fixtures and intercepted failure responses;
  they do not certify delivery of recovery emails or external API execution.
